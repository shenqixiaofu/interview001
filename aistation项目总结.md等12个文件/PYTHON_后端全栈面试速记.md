# Python / FastAPI / MySQL / Redis / WebSocket 后端面试速记

## 1. 先记住 Python 后端到底在做什么

Python 后端主要负责：

- 接收请求
- 校验参数
- 执行业务逻辑
- 读写数据库
- 调用外部服务
- 返回结果

一句话回答：

> Python 后端的核心职责是承接请求、处理业务、管理数据，并保证接口的稳定性、性能和可维护性。

## 2. Python 基础先背什么

### 2.1 `list`、`tuple`、`set`、`dict` 区别

- `list`：有序、可重复、可修改
- `tuple`：有序、可重复、不可修改
- `set`：无序、不可重复
- `dict`：键值对，按 key 查值

一句话回答：

> `list` 适合顺序数据，`tuple` 适合不希望被修改的数据，`set` 适合去重，`dict` 适合按 key 快速查找。

### 2.2 可变对象和不可变对象

常见可变对象：

- `list`
- `dict`
- `set`

常见不可变对象：

- `int`
- `str`
- `tuple`

一句话回答：

> 可变对象修改的是对象本身，不可变对象一旦变更，本质上会生成新对象。

### 2.3 浅拷贝和深拷贝

- 浅拷贝：只拷贝最外层，内部嵌套对象还是共用
- 深拷贝：递归拷贝，完全独立

常见方式：

- 浅拷贝：`copy.copy()`、切片、`dict()`、`list()`
- 深拷贝：`copy.deepcopy()`

一句话回答：

> 浅拷贝只复制外壳，深拷贝会把里面的嵌套对象一起复制。

### 2.4 迭代器和生成器

- 迭代器：实现了 `__iter__()` 和 `__next__()` 的对象
- 生成器：使用 `yield` 生成值的特殊迭代器

优点：

- 节省内存
- 适合处理大数据量或流式数据

一句话回答：

> 生成器本质上是更方便的迭代器，适合按需生成数据而不是一次性全部加载。

### 2.5 装饰器是什么

装饰器本质是：

- 一个函数接收另一个函数
- 在不改原函数代码的前提下增强它

常见用途：

- 日志
- 权限校验
- 缓存
- 统计耗时

一句话回答：

> 装饰器是对函数做“无侵入增强”的语法糖，常用于日志、鉴权、缓存这类横切逻辑。

### 2.6 `*args` 和 `**kwargs`

- `*args`：接收位置参数，变成元组
- `**kwargs`：接收关键字参数，变成字典

一句话回答：

> `*args` 用来接不定位置参数，`**kwargs` 用来接不定关键字参数，适合做通用封装。

## 3. Python 并发和异步必须会的

### 3.1 进程、线程、协程区别

- 进程：资源分配单位
- 线程：CPU 调度单位
- 协程：用户态轻量级并发单元

一句话回答：

> 进程最重，线程次之，协程最轻；Python Web 项目里大量 I/O 场景通常更适合协程。

### 3.2 GIL 是什么

GIL = Global Interpreter Lock，全局解释器锁。

它的影响：

- 同一时刻一个 Python 进程里只有一个线程真正执行 Python 字节码
- 对 I/O 密集型影响不大
- 对 CPU 密集型多线程有影响

一句话回答：

> GIL 让 Python 多线程在 CPU 密集场景下收益有限，但在 I/O 密集场景下仍然有价值。

### 3.3 `async` / `await` 是什么

- `async def` 定义协程函数
- `await` 表示等待一个可等待对象

常见适用场景：

- 数据库异步访问
- HTTP 调用
- WebSocket
- 文件 I/O

一句话回答：

> `async/await` 适合高并发 I/O 场景，它不是让单个逻辑更快，而是提高整体吞吐。

### 3.4 事件循环是什么

事件循环可以理解成：

- 维护一组待执行协程
- 哪个 I/O 完成了就切回来继续执行

一句话回答：

> 事件循环负责调度协程，让程序在等待 I/O 时不阻塞整个线程。

### 3.5 FastAPI 里什么时候该写异步

适合写 `async` 的情况：

- 异步数据库
- 外部 HTTP 请求
- WebSocket 长连接
- 上传下载

不适合盲目写 `async` 的情况：

- 纯 CPU 计算
- 调用的库本身是阻塞的

一句话回答：

> 是否写异步，不看框架潮不潮，而看你的操作是不是 I/O 密集、依赖链是否支持异步。

### 3.6 CPU 密集和 I/O 密集怎么选

- CPU 密集：多进程更合适
- I/O 密集：协程或多线程更合适

面试回答：

> 文件上传、数据库访问、模型接口调用更偏 I/O；图像处理、复杂计算更偏 CPU。

## 4. FastAPI / Flask / Django 你怎么说

### 4.1 FastAPI 为什么常用

FastAPI 优点：

- 上手快
- 类型提示友好
- Pydantic 参数校验清晰
- 自动生成 Swagger 文档
- 天然支持异步

一句话回答：

> FastAPI 适合中小型 API 服务和 AI 应用后端，因为开发效率高、文档清晰、异步支持自然。

### 4.2 Flask 和 Django 区别

- Flask：轻量，灵活，适合自己搭
- Django：大而全，自带很多能力
- FastAPI：现代化 API 框架，类型和异步体验更好

一句话回答：

> Flask 更轻，Django 更全，FastAPI 更适合现代 API 和 AI 场景。

### 4.3 Pydantic 是做什么的

Pydantic 作用：

- 请求参数校验
- 数据类型转换
- 返回模型定义

一句话回答：

> Pydantic 让接口输入输出结构更明确，也减少了手写校验代码。

### 4.4 依赖注入怎么理解

FastAPI 里的依赖注入常用于：

- 获取数据库会话
- 获取当前用户
- 做权限校验

一句话回答：

> 依赖注入的价值是把公共逻辑抽出来复用，比如数据库连接、认证和权限校验。

## 5. 数据库和 SQLAlchemy 你至少会答什么

### 5.1 ORM 是什么

ORM = Object Relational Mapping，对象关系映射。

核心思想：

- 用 Python 对象操作数据库表
- 降低大量手写 SQL 的成本

一句话回答：

> ORM 是把表和对象做映射，让开发更高效，但复杂查询场景仍然要关注底层 SQL。

### 5.2 SQLAlchemy 你怎么理解

SQLAlchemy 提供：

- 模型定义
- 会话管理
- 查询构造
- 事务控制

一句话回答：

> SQLAlchemy 是 Python 里常见 ORM，适合管理模型、事务和查询，但不能因为用了 ORM 就忽略 SQL 性能。

### 5.3 索引是什么

索引作用：

- 加快查询
- 但会增加写入和维护成本

一句话回答：

> 索引本质上是用空间换时间，查询快了，但插入、更新、删除会更贵。

### 5.4 MySQL 事务和 ACID

ACID：

- 原子性
- 一致性
- 隔离性
- 持久性

一句话回答：

> 事务的核心目标是保证一组操作要么都成功，要么都失败，并尽量避免并发下的数据异常。

### 5.5 慢 SQL 怎么排查

常见排查点：

- 有没有索引
- 索引有没有失效
- 查询条件是否合理
- 是否查了不必要字段
- 是否出现大表扫描

一句话回答：

> 慢 SQL 排查核心看执行计划、索引命中、扫描行数和查询字段范围。

### 5.6 N+1 查询问题是什么

N+1 问题就是：

- 先查一批主数据
- 再对每条主数据单独查关联数据

一句话回答：

> N+1 的本质是查询次数过多，通常可以通过预加载或联表查询优化。

## 6. Redis 必会内容

### 6.1 Redis 常见用途

- 缓存
- 验证码
- 分布式锁
- 会话
- 限流

一句话回答：

> Redis 最常见的价值是高性能读写，适合放热点数据和一些需要快速判断的状态。

### 6.2 为什么 Redis 快

原因：

- 基于内存
- 单线程模型简单
- 数据结构高效
- 网络开销低

一句话回答：

> Redis 快的核心是内存访问快、实现简单、数据结构高效。

### 6.3 缓存穿透、击穿、雪崩

- 穿透：查不存在的数据
- 击穿：热点 key 失效瞬间大量请求打到数据库
- 雪崩：大量 key 同时失效

一句话回答：

> 穿透查不到，击穿是热点失效，雪崩是大面积同时失效。

### 6.4 Redis 分布式锁怎么说

常见方案：

- `SET key value NX EX`

要点：

- 加锁要带过期时间
- 解锁要保证删的是自己的锁

一句话回答：

> Redis 分布式锁的核心不是“能不能加锁”，而是“锁是否安全释放”和“超时是否可控”。

## 7. 接口和工程化常见问题

### 7.1 JWT 是什么

JWT 常用于：

- 用户登录后标识身份
- 服务端解析 token 获取用户信息

一句话回答：

> JWT 适合做无状态身份标识，但如果要做强制下线或黑名单，通常还要配合 Redis。

### 7.2 什么是幂等接口

幂等就是：

- 同一个请求重复执行
- 结果不会被错误地重复影响

一句话回答：

> 幂等的核心是防止重复请求造成重复写入、重复扣减或重复创建。

### 7.3 限流怎么理解

限流目的是：

- 保护系统
- 防止接口被刷

常见方式：

- 固定窗口
- 滑动窗口
- 令牌桶

一句话回答：

> 限流本质是保护服务稳定，不让突发流量把系统打崩。

### 7.4 文件上传要注意什么

常见关注点：

- 文件大小
- 文件类型
- 存储位置
- 唯一命名
- 安全校验

一句话回答：

> 文件上传不只是“把文件收上来”，还要考虑安全、命名、存储和访问控制。

### 7.5 日志排查怎么做

常见命令：

- `tail -f`
- `grep`
- `less`
- `ps`

一句话回答：

> 排查线上问题时先按时间点和错误关键字看日志，再结合接口、进程和最近发布信息定位。

## 8. WebSocket 和实时能力要会说

### 8.1 WebSocket 和 HTTP 区别

- HTTP 更适合请求一次、返回一次
- WebSocket 适合长连接和双向通信

一句话回答：

> WebSocket 更适合聊天、流式输出、状态通知这种需要实时双向通信的场景。

### 8.2 Python 后端为什么会用 WebSocket

常见场景：

- AI 流式回复
- 在线客服
- 实时消息
- 状态推送

一句话回答：

> 用 WebSocket 主要是为了减少轮询开销，提升实时性，并支持服务端主动推送。

### 8.3 WebSocket 服务端要注意什么

注意点：

- 连接管理
- 心跳保活
- 断线清理
- 鉴权
- 消息路由

一句话回答：

> WebSocket 真正难点不在建立连接，而在连接生命周期管理和消息状态一致性。

## 9. AI 应用后端常见问题

### 9.1 OpenAI Compatible API 是什么

它的意思是：

- 接口风格兼容 OpenAI
- 可以切换不同模型服务商

一句话回答：

> OpenAI Compatible API 的价值是统一调用方式，降低模型切换成本。

### 9.2 RAG 是什么

RAG = Retrieval-Augmented Generation，检索增强生成。

核心流程：

- 文档解析
- 切片
- 向量化
- 检索
- 拼 Prompt
- 生成答案

一句话回答：

> RAG 的核心不是让模型“背全文”，而是先检索相关内容，再基于相关上下文回答。

### 9.3 为什么要切片

原因：

- 控制上下文长度
- 提高检索精度
- 降低 token 成本

一句话回答：

> 切片是在“语义完整”和“检索精度”之间做平衡。

### 9.4 向量库为什么有必要

向量库适合：

- 语义检索
- 相似度搜索

一句话回答：

> 向量库不是替代 MySQL，而是补足传统数据库不擅长的语义相似检索。

### 9.5 流式输出为什么重要

好处：

- 用户更快看到结果
- 体验更像对话
- 便于中途停止

一句话回答：

> 流式输出不一定让总耗时更短，但能显著提升用户体感。

## 10. 全栈工程师面试里你要会怎么串起来

你可以这样答：

> 我做 Python 后端时，通常会先用 FastAPI 定义接口和参数模型，用 SQLAlchemy 处理数据库访问，用 Redis 做缓存、限流或状态存储；如果是 AI 场景，会再接模型接口、向量检索和 WebSocket 流式输出，把聊天、知识库或本地任务链路串起来。

## 12. 最后给你一个超短背诵版

### Python

> Python 基础重点是数据结构、可变与不可变、装饰器、生成器和异步编程。

### FastAPI

> FastAPI 的优势是开发快、参数校验清晰、文档自动生成、异步支持自然，适合做 API 服务和 AI 应用后端。

### MySQL

> MySQL 重点看索引、事务、慢 SQL 和执行计划，核心是把查询写对、把索引用对。

### Redis

> Redis 常用于缓存、限流、分布式锁和会话管理，重点要分清穿透、击穿和雪崩。

### WebSocket

> WebSocket 适合实时推送和流式对话，难点在连接管理、心跳保活和消息一致性。

### AI 应用

> RAG 的核心是文档解析、切片、向量化、检索和生成；流式输出和知识检索是 AI 应用后端最常见的落地点。
