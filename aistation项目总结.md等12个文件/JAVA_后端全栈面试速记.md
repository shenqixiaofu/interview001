# Java / Spring Boot / MySQL / Redis / MQ 全栈面试速记

## 1. 先记住后端到底在做什么

后端主要负责：

- 接收请求
- 校验参数
- 执行业务逻辑
- 读写数据库
- 返回结果

一句话回答：

> 后端的核心职责是承接请求、处理业务、管理数据，并保证性能、稳定性和安全性。

## 2. Java 基础先背什么

### 2.1 JDK / JRE / JVM 区别

- `JDK`：开发工具包，包含编译器、运行工具、JRE
- `JRE`：Java 运行环境
- `JVM`：Java 虚拟机，负责真正执行字节码

一句话回答：

> JDK 是开发用的，JRE 是运行用的，JVM 是真正执行 Java 字节码的虚拟机。

### 2.2 面向对象三大特性

- 封装
- 继承
- 多态

一句话回答：

> 封装是隐藏实现细节，继承是复用父类能力，多态是同一接口在不同对象上有不同表现。

### 2.3 `==` 和 `equals`

- `==` 比较地址，基本类型比值
- `equals` 一般比较内容

例子：

```java
String a = new String("abc");
String b = new String("abc");

System.out.println(a == b); // false
System.out.println(a.equals(b)); // true
```

### 2.4 `String` / `StringBuilder` / `StringBuffer`

- `String` 不可变
- `StringBuilder` 可变，线程不安全，性能高
- `StringBuffer` 可变，线程安全，性能低一点

### 2.5 `ArrayList` 和 `LinkedList`

- `ArrayList`：底层数组，查快，尾插快，中间插删慢
- `LinkedList`：底层链表，插删方便，查找慢

### 2.6 `HashMap` 和 `ConcurrentHashMap`

- `HashMap` 线程不安全
- `ConcurrentHashMap` 线程安全，适合并发场景

## 3. Java 集合你至少会答什么

常见集合：

- `List`：有序可重复
- `Set`：无序不可重复
- `Map`：键值对

最常见实现类：

- `ArrayList`
- `LinkedList`
- `HashSet`
- `HashMap`
- `TreeMap`

面试回答：

> 选集合时主要看是否需要顺序、是否允许重复、是否要按 key 查找，以及是否存在并发需求。

## 4. 异常是什么

Java 异常分两类：

- `Checked Exception`：编译期异常，必须处理
- `RuntimeException`：运行时异常，不强制处理

常见异常：

- `NullPointerException`
- `IndexOutOfBoundsException`
- `IllegalArgumentException`

一句话回答：

> 编译期异常强调显式处理，运行时异常更偏程序逻辑问题。

## 5. Java 并发必须会的

### 5.1 线程和进程

- 进程是资源分配单位
- 线程是 CPU 调度单位
- 一个进程里可以有多个线程

### 5.2 创建线程方式

- 继承 `Thread`
- 实现 `Runnable`
- 实现 `Callable`
- 使用线程池

实际开发里最常用的是线程池。

### 5.3 线程池为什么重要

线程池作用：

- 复用线程
- 降低频繁创建销毁开销
- 控制并发数量
- 便于任务管理

常见参数：

- 核心线程数
- 最大线程数
- 队列
- 拒绝策略

面试回答：

> 线程池的核心价值是复用线程和控制并发，避免线程无限创建导致系统资源被打满。

### 5.4 `synchronized` 和 `volatile`

`synchronized`：

- 保证原子性
- 保证可见性
- 保证有序性

`volatile`：

- 只保证可见性
- 保证一定程度有序性
- 不保证复合操作原子性

### 5.5 什么是 CAS

- CAS = Compare And Swap
- 比较旧值是否还是预期值
- 是则更新，否则重试

常用于无锁并发。

### 5.6 死锁是什么

死锁就是多个线程互相等待对方释放资源，导致谁都执行不下去。

产生死锁的经典条件：

- 互斥
- 持有并等待
- 不可剥夺
- 循环等待

## 6. JVM 面试基础

### 6.1 JVM 内存结构

常见理解：

- 堆：对象实例
- 栈：方法调用、局部变量
- 方法区：类信息、常量、静态变量

### 6.2 垃圾回收

GC 主要回收堆里的无用对象。

常见判断对象是否存活：

- 引用计数法
- 可达性分析

Java 主要用可达性分析。

### 6.3 常见垃圾回收器

- Serial
- ParNew
- CMS
- G1

面试不一定要背特别深，但至少知道：

> G1 适合大内存场景，目标是更可控的停顿时间。

## 7. Spring 是什么

Spring 核心是两个：

- IOC
- AOP

### 7.1 IOC

IOC = Inversion of Control，控制反转。

本来对象应该由程序员自己 `new`，现在交给 Spring 容器管理。

常见效果：

- 对象创建统一管理
- 依赖注入更方便
- 更易测试

### 7.2 AOP

AOP = 面向切面编程。

适合处理横切逻辑：

- 日志
- 权限
- 事务
- 监控

一句话回答：

> IOC 解决对象管理问题，AOP 解决通用逻辑抽离问题。

大致流程：

1. 实例化
2. 依赖注入
3. 初始化
4. 使用
5. 销毁

常见扩展点：

- `@PostConstruct`
- `InitializingBean`

## 9. Spring Boot 为什么常用

因为它帮你做了：

- 自动配置
- 内嵌 Web 容器
- 快速启动
- 统一约定优于配置

一句话回答：

> Spring Boot 是 Spring 的工程化增强，核心价值是自动装配和快速开发。

## 10. 自动装配是什么

自动装配就是：

- 根据依赖
- 根据配置
- 根据条件注解

自动帮你创建 Bean。

常见注解：

- `@SpringBootApplication`
- `@Configuration`
- `@Bean`
- `@Component`
- `@Service`
- `@Repository`

## 11. 常见 Spring 注解

- `@Component`：普通组件
- `@Service`：业务层
- `@Repository`：持久层
- `@Controller` / `@RestController`：控制器
- `@Autowired`：依赖注入
- `@Value`：注入配置

## 12. 事务是什么

事务的本质是：一组操作要么都成功，要么都失败。

### ACID

- `A` 原子性
- `C` 一致性
- `I` 隔离性
- `D` 持久性

面试回答：

> 事务的核心是保证业务操作的完整性和一致性，最常见就是下单、扣库存、写支付记录这类操作必须放在同一个事务里。

## 13. `@Transactional` 常见坑

- 方法必须被 Spring 代理到
- 同类内部自调用可能失效
- 只有运行时异常默认回滚

一句话回答：

> `@Transactional` 本质依赖代理，如果事务方法没有经过代理调用，事务可能不生效。

## 14. MySQL 必会基础

### 14.1 索引是什么

索引就是帮助数据库更快定位数据的数据结构。

### 14.2 为什么 MySQL 常说 B+ 树

因为 InnoDB 的索引底层常用 B+ 树。

优势：

- 多叉树，高度低
- 适合磁盘 IO
- 范围查询友好

### 14.3 聚簇索引和二级索引

- 聚簇索引：数据和索引放一起，主键索引通常是聚簇索引
- 二级索引：先查索引，再回表找数据

### 14.4 什么情况索引会失效

常见情况：

- 对索引列做函数
- 隐式类型转换
- like 以 `%` 开头
- 违反最左前缀原则

## 15. MySQL 事务隔离级别

四种隔离级别：

- 读未提交
- 读已提交
- 可重复读
- 串行化

MySQL InnoDB 默认是：

- 可重复读

### 会出现的问题

- 脏读
- 不可重复读
- 幻读

## 16. MVCC 是什么

MVCC = 多版本并发控制。

它的核心思路：

- 一条数据不只一个版本
- 读的时候读适合当前事务可见的版本
- 从而减少读写冲突

面试回答：

> MVCC 通过数据多版本机制提升并发能力，让普通读操作尽量不阻塞写操作。

### Java 层常见锁

## 18. 什么是慢 SQL

慢 SQL 通常指执行时间明显偏长的 SQL。

排查方向：

- 有没有索引

- SQL 是否写法不合理
- 数据量是否太大
- 是否回表过多

常见工具：

- `EXPLAIN`

## 19. Redis 必会内容

### 19.1 Redis 是什么

Redis 是基于内存的高性能 key-value 存储。

常见用途：

- 缓存
- 分布式锁
- 计数器
- 排行榜
- 会话存储

### 19.2 Redis 常见数据结构

- `String`
- `Hash`
- `List`
- `Set`
- `ZSet`

### 19.3 为什么 Redis 快

- 基于内存
- 单线程模型避免锁竞争
- 数据结构简单
- IO 模型高效

## 20. 缓存穿透 / 击穿 / 雪崩

### 穿透

查一个根本不存在的数据，缓存和数据库都没有，每次都打到数据库。

解决：

- 布隆过滤器
- 缓存空值

### 击穿

热点 key 正好过期，大量请求同时打数据库。

解决：

- 热点 key 永不过期
- 加互斥锁

### 雪崩

大量 key 同时过期，数据库瞬间被打爆。

解决：

- 过期时间加随机值
- 多级缓存
- 熔断降级

## 21. Redis 分布式锁

最常见：

- `SET key value NX EX seconds`

需要注意：

- 加锁成功后要设置过期时间
- 解锁要保证只能删自己的锁

面试回答：

> Redis 分布式锁的核心是原子加锁、超时释放和避免误删他人锁。

## 22. 消息队列为什么要用

消息队列常见价值：

- 解耦
- 削峰
- 异步

例子：

- 下单后发积分、发优惠券、发通知，不一定同步做完

## 23. MQ 常见问题

### 23.1 重复消费

消息可能被重复投递。

解决：

- 幂等处理

### 23.2 消息丢失

可能在生产、存储、消费阶段丢。

解决：

- 生产确认
- 持久化
- 消费确认

### 23.3 消息顺序

顺序消费一般更难，需要分区、同 key 同队列这类策略。

### 23.4 幂等是什么

同一个请求执行一次和执行多次，最终结果一致。

常见手段：

- 唯一索引
- 去重表
- 状态机控制

## 24. 接口设计常见问题

### RESTful 是什么

RESTful 是一种接口设计风格：

- 资源化
- URL 表示资源
- HTTP 方法表示动作

例如：

- `GET /users/1`
- `POST /orders`
- `PUT /orders/1`
- `DELETE /orders/1`

### 为什么要做参数校验

因为后端不能相信前端。

常见校验：

- 非空
- 长度
- 格式
- 枚举值

## 25. 鉴权你怎么理解

常见流程：

1. 登录成功
2. 服务端签发 token
3. 客户端后续请求带 token
4. 服务端校验 token

常见方式：

- Session
- JWT

## 26. 什么是幂等接口

典型例子：

- 支付回调
- 重复提交订单
- MQ 重试消费

目标是避免多次请求造成重复写入。

## 28. 全栈工程师面试里你要会怎么串起来

一个完整请求链路通常是：

1. 前端发请求
2. 网关 / 服务端接口接收
3. 参数校验
4. 进入 service
5. 查 Redis / 查 MySQL
6. 事务处理
7. 必要时发 MQ
8. 返回前端

你要能把整条链路讲明白。

## 29. 面试最常见问法和标准答法

### 题：Spring Boot 为什么好用

答：

> 因为它提供自动装配和约定优于配置，能快速搭建项目，减少大量样板代码。

### 题：事务什么时候会失效

答：

> 常见情况是同类内部自调用、异常类型不触发回滚、方法没经过 Spring 代理。

### 题：MySQL 索引底层为什么用 B+ 树

答：

> 因为 B+ 树高度低、磁盘 IO 次数少，并且天然适合范围查询。

### 题：Redis 为什么快

答：

> 因为它基于内存、数据结构简单、单线程避免锁竞争、网络模型高效。

### 题：缓存击穿怎么处理

答：

> 热点 key 过期瞬间大量请求会打数据库，一般用互斥锁、逻辑不过期或热点预热处理。

### 题：MQ 为什么会重复消费，怎么解决

答：

> 因为网络、重试、消费确认机制都会导致重复投递，所以消费端必须做幂等。

### 题：什么是幂等

答：

> 同一操作执行一次和执行多次结果一致，常用于支付、下单、回调、消息消费等场景。

你可以直接背：

> Java 后端的核心是承接请求、处理业务和管理数据。Spring 里 IOC 负责对象管理，AOP 负责日志、事务这类横切逻辑，Spring Boot 通过自动装配提升开发效率。MySQL 重点要掌握索引、事务、MVCC 和锁；Redis 重点是缓存、分布式锁以及穿透击穿雪崩；MQ 重点是解耦、削峰和幂等。系统设计上要能说明一条请求从前端进入后端，再到缓存、数据库、消息队列的完整链路。
